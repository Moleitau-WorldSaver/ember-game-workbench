# Issue #003：建立任务数据模型和文件存储

## 类型

Feature

## 状态

Draft

## 背景

任务需要在多个 Session 之间共享，并且应当以普通项目文件的形式持久化。单任务单文件可以降低并发修改时的相互影响。

## 用户故事

作为开发者，我希望任务在项目根目录下稳定保存，Session 重启后仍然可以读取。

## 最小范围

1. 创建项目根目录下的 `.tinyagent/tasks/`。
2. 定义任务 ID、标题、描述、状态、时间、归档前状态和版本号。
3. 每个任务保存为一个独立 JSON 文件。
4. 提供任务文件读取、写入和目录初始化接口。

## 非目标

- 不实现任务状态流转。
- 不实现 Session 自动发现。
- 不实现总索引文件和数据库。

## 验收标准

- 任务可以写入并重新读取。
- 任务文件包含约定字段和初始版本号。
- 任务目录不存在时可以安全初始化。
- 单个损坏或无效文件不会阻止其他任务读取。

## 技术约束

- 文件格式使用 UTF-8 JSON。
- 写入接口为后续原子写入和版本校验保留扩展点。
