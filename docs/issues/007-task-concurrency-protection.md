# Issue #007：实现并发修改保护

## 类型

Infrastructure

## 状态

Draft

## 背景

多个 Session 可以同时编辑同一项目任务。没有并发保护时，后写入的内容可能静默覆盖先写入的内容。

## 用户故事

作为开发者，我希望并发修改同一任务时收到明确冲突，而不是丢失其他 Session 的更新。

## 最小范围

1. 为任务修改增加版本号校验。
2. 使用临时文件加原子替换写入。
3. 在版本不一致时拒绝提交。
4. 返回当前版本和可恢复的冲突结果。
5. 让创建不同任务的操作可以并行。

## 非目标

- 不做实时推送。
- 不做自动冲突合并。
- 不锁定任务归属某个 Session。

## 验收标准

- 同一旧版本的第二次修改会被拒绝。
- 先提交的内容不会被后提交者覆盖。
- 不同任务可以同时修改。
- 归档和恢复同样执行版本校验。
- 异常中断不会留下会被误读的正式任务文件。

## 技术约束

- 版本号单调递增。
- 并发保护不依赖常驻后台服务。
