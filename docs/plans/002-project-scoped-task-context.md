# Plan #002：项目级任务上下文与并发任务管理

## 目标

建立项目级任务管理的第一条可执行闭环：Session 根据当前工作目录识别最近的 Git 项目，读取该项目的任务，支持多个 Session 同时查看和编辑，并通过版本校验避免静默覆盖。

第一版只处理项目任务，不引入总根目录任务、跨项目任务、实时协同编辑或自动任务分配。

## 技术决策

- **项目边界**：以当前目录向上查找到的最近 Git 根目录作为项目根目录。
- **任务位置**：项目根目录下的 `.tinyagent/tasks/`。
- **存储方式**：每个任务一个 JSON 文件，不使用共享总索引文件。
- **任务字段**：保留稳定 ID、标题、描述、状态、时间字段、归档前状态和版本号。
- **状态集合**：`todo`、`in_progress`、`blocked`、`done`、`archived`。
- **归档语义**：归档隐藏任务但不删除文件，恢复时回到归档前状态。
- **并发策略**：原子写入加版本号校验。同一任务发生版本冲突时拒绝静默覆盖。
- **Session 语义**：Session 读取当前项目的任务列表，不持久化 Session 与任务的绑定关系。
- **Git 行为**：程序不自动提交任务文件，是否纳入版本控制由项目自行决定。
- **入口策略**：核心模块先提供稳定的领域接口，实际 Session 入口在后续 Issue 中接入。

## 完成定义

- Session 能正确识别最近 Git 项目。
- 任务只从当前项目的 `.tinyagent/tasks/` 读取。
- 多个 Session 可以共享同一项目的任务。
- 合法状态转换和归档恢复可用。
- 同一任务的并发修改不会静默覆盖。
- 没有 Git 根目录时不会读取其他项目任务。
- 测试和使用说明覆盖第一版边界。

## 非目标

- 不做总根目录任务。
- 不做跨项目任务。
- 不做实时推送和协同编辑。
- 不做自动任务分配。
- 不做任务物理删除。
- 不做 Git 自动提交。
- 不做 GitHub Issue 自动同步。
